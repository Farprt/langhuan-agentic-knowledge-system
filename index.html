工作流程

找到线索，再回到原文。

目录告诉你位置，检索补充跨目录的候选，原文提供判断依据。三步可以独立使用，也能接入现有 Agent 工作流。

01 / LOCATE

恢复知识位置

从文件路径、标题和别名定位目标，查看结构与已有链接。

  • 保留原有目录组织
  • 不依赖上一次对话的记忆
catalog find / context

02 / DISCOVER

发现补充来源

结合语义与关键词检索，在不同目录中找相关材料，按文件汇总候选。

  • 保留命中章节和来源路径
  • 按任务选择检索范围
ask --output candidates.json

03 / READ

打开原文核对

选择来源，直接读取当前 Markdown 的相关小节，带着上下文形成结论。

  • 选择来源，而非照抄摘要
  • 返回范围与截断状态明确
catalog read --sources …

工程基础

简单的入口，清晰的底层。

公开版本提供演示知识库和自动测试。检索提供候选，内容是否适用，仍需 Agent 结合来源判断。

解析

理解 Obsidian，而不只是读取纯文本

YAML 元数据、双向链接、嵌入引用和标题层级都会保留在知识片段中。

发现与阅读

从检索候选继续打开原文

语义向量与 BM25 结果经 RRF 融合，再由可选本地交叉编码器二次排序；按来源编号选择笔记后，Langhuan 读取当前 Markdown，而不是把索引摘要当作原文。

可靠性

只更新发生变化的文件

文件哈希用于识别新增、修改和删除；索引完整写入后再替换旧版本，并检查知识片段 ID 是否一致。

项目验证

可复现测试解析 / 检索 / 直接读取 / 索引一致性
离线 demo无需模型或云账号
公开边界候选不冒充事实，原文按需打开

公开仓库包含演示知识库、测试代码和可复现的命令。

快速开始 / PYTHON 3.11+

从一个离线 Demo 开始。

先用合成示例体验检索与阅读，再通过配置接入自己的知识库。默认演示不下载模型；语义模型和外部服务按需启用。

数据边界

知识内容和索引默认保留在本地

DEFAULT

默认留在本地

原始 Markdown、本地索引、模型缓存和 JSONL 事件；凭据不会写入项目配置或导出事件。

按需启用

外部分析与长期记忆

AgentLoop 和 Langfuse 由显式命令按需导出；Honcho 仅提供集成约定，由外部 Agent 写入稳定结论。

不提交

本地敏感文件

私有知识、真实日志、数据库、模型缓存、凭据和第三方二进制不会提交到 Git。
