工作流程

从知识库结构到来源阅读

Catalog 提供位置线索，混合检索发现内容关联，阅读命令打开当前 Markdown 原文；任务上下文与本地追踪按需要使用。

01 / CONFIG

知识库配置

一个 langhuan.toml 描述目录、YAML 字段、检索范围和非敏感运行选项。

  • Obsidian 结构化解析
  • 项目级检索范围
  • 路径与配置可移植

02 / DISCOVER

定位并阅读来源

按路径、标题或语义找到候选文件，选择后从当前 Markdown 读取指定小节。

  • 结果保留原始相对路径
  • 多来源可一次选择
  • 字符上限明确，正文在本地读取

03 / OPTIONAL

按需运行记录

需要回看操作耗时或状态时，可在本地 JSONL 记录步骤；AgentLoop 和 Langfuse 是可选分析出口。

  • 不作为普通阅读前置
  • 正文采集默认关闭
  • 导出与检索分离

核心能力

解析、检索与增量维护

公开版本提供演示知识库和自动测试；实际生产环境已运行在数千个知识片段的私人知识库中。

解析

理解 Obsidian，而不只是读取纯文本

YAML 元数据、双向链接、嵌入引用和标题层级都会保留在知识片段中。

发现与阅读

从检索候选继续打开原文

语义向量与 BM25 结果经 RRF 融合，再由可选本地交叉编码器二次排序；按来源编号选择笔记后，Langhuan 读取当前 Markdown，而不是把索引摘要当作原文。

可靠性

只更新发生变化的文件

文件哈希用于识别新增、修改和删除；索引完整写入后再替换旧版本，并检查知识片段 ID 是否一致。

项目验证

可复现测试解析 / 检索 / 直接读取 / 索引一致性
离线 demo无需模型或云账号
公开边界候选不冒充事实，原文按需打开

公开仓库包含演示知识库、测试代码和可复现的命令。

FIVE-MINUTE PATH

先跑通离线 demo，再决定是否启用模型与云端集成

首次体验不要求 Docker、Honcho、AgentLoop、Langfuse 或任何云账号。程序不会自动下载生产模型，需要时可单独准备本地模型。

01 Demo02 Init03 Doctor04 Index05 Ask
PowerShell / Bash

            git clone https://github.com/Farprt/langhuan-agentic-knowledge-system.git
            cd langhuan-agentic-knowledge-system
            python -m pip install -e .
            langhuan demo
            langhuan init --vault ./examples/demo-vault
            langhuan doctor
            langhuan index
            langhuan ask "events include query content" --output candidates.json
            langhuan catalog read --sources candidates.json --select 1 --compact

数据边界

知识内容和索引默认保留在本地

DEFAULT

默认留在本地

原始 Markdown、本地索引、模型缓存和 JSONL 事件；凭据不会写入项目配置或导出事件。

按需启用

外部分析与长期记忆

AgentLoop 和 Langfuse 由显式命令按需导出；Honcho 仅提供集成约定，由外部 Agent 写入稳定结论。

不提交

本地敏感文件

私有知识、真实日志、数据库、模型缓存、凭据和第三方二进制不会提交到 Git。

实现范围

核心模块与可选服务

核心模块

Obsidian 解析、按标题分块、混合检索、增量同步、文件结构索引、任务上下文、本地运行记录与一致性检查。

可选能力

可加载已准备好的本地 BGE 和交叉编码器模型；运行记录可按需导出到 AgentLoop 或 Langfuse，Honcho 集成按约定由外部 Agent 完成。
